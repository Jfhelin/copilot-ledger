# Publishing Plan

## Publishing Principle

LinkedIn is the primary publishing surface. GitHub Pages is the evidence layer.

Each published topic should have:

1. A short LinkedIn post
2. A 60–120 second native LinkedIn video or screen recording
3. A GitHub Pages experiment page
4. A Copilot Ledger export or evidence section

## Suggested Launch Order

The file numbers under `experiments/` (`01`–`08`) are just stable IDs, **not**
the publishing order. Publish in this order instead:

1. Context Quality — The README was cheap. Finding it wasn't.
2. Agent Planning — I thought the answer was expensive. The plan was.
3. Cache Behavior — Your "cold" session isn't cold (~9,700 tokens pre-cached).
4. Tool & Skill Overhead — A quarter of every call is tool defs; changing them
   busts the cache. *(Seeded, N=1, under investigation — publish after a second
   run isolates skill-only overhead.)*
5. Caveman Prompting — Less than 3% realistic savings in a 107-credit session.
6. Model Selection — The biggest cost lever often is not prompt length.
7. Prompt Precision — Vague prompts make agents explore more.
8. Context Growth — Long sessions behave differently than short ones.

## Cadence

Publish one LinkedIn post every 7–10 days.

Prepare at least 3–4 experiment pages before publishing the first post.
